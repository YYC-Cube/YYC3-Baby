## 三、可行性严格审核

### 3.1 技术前提（具备 ✅）

| 前提 | 兄弟项目 | 统一基线 |
| ---- | ---- | ---- |
| Tailwind CSS v4 + CSS 变量 token | ✅ | ✅ |
| shadcn/ui + Radix UI | ✅ | ✅ |
| next-themes 主题 Provider | ✅ | ✅ |
| `[data-theme]` 机制 | ✅ 已有 | ❌ 需建立 |
| 暗色主题基建（.dark / color-scheme） | ✅ | ✅ |

### 3.2 可行性风险点

| 风险 | 等级 | 说明与缓解 |
| ---- | ---- | ---- |
| **SSR 水合闪烁** | 🟡 中 | Aurora 为暗色主题，若 `<html>` 初始态为 light，首屏会白闪。缓解：`next-themes` 自带 `suppressHydrationWarning` + 内联脚本，注册时启用 `disableTransitionOnChange` |
| **动效性能开销** | 🟡 中 | 573 行 CSS + 5 Orb + 20 粒子持续动画。缓解：GPU 合成（`will-change: transform`）、`animation-play-state` 在非活跃标签页暂停、组件层 `pointer-events: none` |
| **CSS 全量打包** | 🟢 低 | aurora.css 仅作用于 `[data-theme='aurora']` 作用域，未激活时零渲染开销；573 行 CSS 增量 ~15KB gzip，可接受 |
| **无障碍退化** | 🟡 中 | 高频动画对视障/前庭敏感用户不友好。必须加 `@media (prefers-reduced-motion: reduce)` 全局降级（方案未提及） |
| **颜色对比度** | 🟡 中 | Aurora 深底 + 高亮绿 `#00ff87` 对比度约 6.4:1（达标），但 `#ff6b6b` 红在深底 ~3.9:1（仅大字/装饰可用）。需建立 AA 验收 |

### 3.3 结论

方案技术上**完全可行**，核心动作是 CSS token + Provider 注册 + 背景组件接入，均为低风险改造。主要不确定性不在"能不能做"，而在"做进哪个仓库 + 验收标准是什么"。

## 四、完整性严格审核（方案缺口）

方案 Step 1-5 + 工作量估算较完整，但存在 **4 项工程缺口**：

### 缺口 1：缺完整语义 token 映射（不只是主色）
方案只给出 `--color-primary / --bg-app / --fg-default` 等 8 个变量。兄弟项目 globals.css 的 token 体系（L400 注释"语义 token 单一来源"）实际包含 shadcn 全量语义变量：`--background / --foreground / --card / --border / --input / --ring / --destructive / --muted-foreground / --accent-foreground` 等。**Aurora 必须补齐这些**，否则 shadcn 组件（Dialog/Popover/Select 等）在 Aurora 下会回退到默认色。

**补充建议的完整 token 集**（Aurora 深色语义）：
```css
[data-theme='aurora'] {
  --background: #0a1628;        --foreground: #f0f6ff;
  --card: rgba(255,255,255,.06); --card-foreground: #f0f6ff;
  --popover: #0d1b30;            --popover-foreground: #f0f6ff;
  --primary: #00ff87;            --primary-foreground: #06251a;
  --secondary: #6c5ce7;          --secondary-foreground: #ffffff;
  --muted: rgba(255,255,255,.08);--muted-foreground: #8ba3c4;
  --accent: rgba(0,255,135,.14); --accent-foreground: #00ff87;
  --destructive: #ff6b6b;        --destructive-foreground: #ffffff;
  --border: rgba(0,255,135,.16); --input: rgba(255,255,255,.12);
  --ring: #00ff87;
  color-scheme: dark;
}
```

### 缺口 2：缺降级与可访问性策略
- `@media (prefers-reduced-motion: reduce)` 下禁用全部动画
- 文档焦点环（`--ring`）在亮色/暗色下的可见性
- 滚动条 / `::selection` / 占位图在 Aurora 下的观感

### 缺口 3：缺 SSR/水合与 Next 集成细节
- `AuroraBackground` 必须是 `'use client'`，且背景层建议挂 `position: fixed; inset: 0; z-index: -1; pointer-events: none`
- 主题注册后 `ThemeSwitcher` 的 icon/文案；`THEME_IDS` 顺序（建议 `default → cyberpunk → liquid → aurora` 按色系递进）
- 双仓库同步策略（见 §1）

### 缺口 4：缺验收标准
建议定义可量化验收：
| 项 | 标准 |
| ---- | ---- |
| WCAG 对比度 | 正文文本 ≥ 4.5:1，大字 ≥ 3:1 |
| 动效帧率 | 60fps（DevTools 性能面板，Aurora 背景激活时） |
| 构建门禁 | tsc 0 错误 · 测试全绿 · 包体增量 < 50KB gzip |
| 回归覆盖 | 四主题 × 关键页面（Home/Growth/Settings）截图对照 |

## 五、建设性专业建议（深化方案）

### 建议 A：分两层落地 —— "机制"与"主题"
```
L1 主题机制（一次性）┐
  建立 data-theme + 完整语义 token 基线（含 4 缺口补齐）
L2 主题资产（增量）┐
  aurora token → 动效 CSS → Background → 表面覆盖 → Switcher
```
机制层做扎实，后续每加一个主题只需重复 L2，边际成本递减。**这符合"五标准"中的标准化/自动化原则。**

### 建议 B：动效 CSS 采用"作用域 + 降级"双保险
```css
[data-theme='aurora'] .aurora-breathe { animation: breathe 3s ease-in-out infinite; }
@media (prefers-reduced-motion: reduce) {
  [data-theme='aurora'] .aurora-breathe,
  [data-theme='aurora'] .aurora-border-flow { animation: none; }
}
```

### 建议 C：组件 token 化用"新增适配类"渐进替换（不一次性改 300+ 处三元）
新增语义工具类（`.text-adaptive` / `.bg-surface` / `.border-soft`）→ 新组件直接用 → 旧组件按页迁移 → 迁移完删除三元。**每个 commit 可独立验证，风险可控。**

### 建议 D：评估是否把 `themes/` 参考目录"接线"为真实现
统一基线的 `themes/{default,cyberpunk,liquid}` 目前是 Figma 参考（未接线）。若走路径 A，可直接把兄弟项目的 `data-theme` 机制落地到统一基线，并顺手把参考目录升级为可用主题 —— 一举消除"三套主题参考长期悬空"的现状。

### 建议 E：明确 V1/V2/V3 归档节奏
方案建议清理 V1/V2/V3，**认同但建议后置到 Aurora 融合完成并验收后**（避免融合过程中需要参考 V3 的 ThemeToggle 与 V4 的差异实现）。归档时保留 V4 权威副本 + 更新 `docs/README.md`。
