 维度           │ 评估           │ 风险点                                     │ 解决方案

### 1.2 功能兼容性分析 ⭐⭐⭐⭐⭐

  功能集合关系图：
  yyc3-xy-01 (全集基础) ⊇ yyc3-xy-02 (AI增强) ⊇ yyc3-xy-03 (架构增强) ⊇ yyc3-xy-05 (特色功能)

• 路由层： app/  目录下的页面可物理合并，通过配置区分路由优先级。

• 资源层： docs/  和  public/  资源可完全合并，建立索引。

结论： 功能互补性强，无互斥逻辑，合并后可实现 1+1+1+1 > 4 的效果。

## ⚙️ 第五部分：关键技术决策与避坑指南

### 1. 依赖冲突解决策略

• React DnD:  xy-05  使用旧版， xy-02  使用  react-dnd  (16.x) 和  react-beautiful-dnd  (13.x)。
  • 决策: 统一升级至  @dnd-kit/core  或保留  react-dnd  16.x，移除  react-beautiful-dnd  (已停止维护)。
• AI SDK:  xy-01  (v5),  xy-02  (v6)。
  • 决策: 升级至 v6，需修改  streamText  等新 API 的调用方式。


### 2. 路由冲突处理

•  xy-01  和  xy-02  都有  /growth 。
  • 决策: 保留  xy-01  的 UI 结构，注入  xy-02  的业务逻辑和沫语数据模型。


### 3. 样式冲突处理

• Tailwind 类名重复。
  • 决策: 引入  tailwind-merge  工具函数  cn() ，强制组件样式隔离。


### 4. 文档库过大

• 1000+ Markdown 文件影响 Git 性能。
  • 决策: 文档库使用 Git Submodule 或者独立存放在 MinIO/OSS 对象存储中，应用运行时动态拉取。
