## 2. 概述

### 2.1 文档目的

本文档定义了YYC³ AI小语智能成长守护系统的组件开发规范，包括组件设计原则、结构组织、命名规范、代码风格、Props设计、状态管理等方面的内容，旨在确保团队开发的组件具有一致性、可维护性和可复用性。

### 2.2 适用范围

本规范适用于YYC³ AI小语智能成长守护系统的所有前端组件开发，包括UI组件、功能组件和业务组件。

### 2.3 术语定义

| 术语 | 解释 |
|------|------|
| 组件 | 可复用的UI元素，包含结构、样式和行为 |
| UI组件 | 基础界面组件，如按钮、输入框、模态框等 |
| 功能组件 | 提供特定功能的组件，如表单、图表、日历等 |
| 业务组件 | 与业务逻辑紧密相关的组件，如成长记录卡片、AI聊天窗口等 |
| Props | 组件的输入参数，用于父组件向子组件传递数据 |
| State | 组件内部的状态管理，用于跟踪组件的变化 |
| Hooks | React 16.8+ 新增的特性，用于在函数组件中使用状态和其他React特性 |

## 3. 组件设计原则

### 3.1 单一职责原则

- 每个组件只负责一个特定的功能
- 组件的代码量不宜过大，一般不超过200行
- 如果组件功能过于复杂，应考虑拆分为多个子组件

### 3.2 可复用性原则

- 组件应设计为通用的、可复用的
- 避免组件与特定业务逻辑强耦合
- 使用Props和上下文提供灵活性

### 3.3 可维护性原则

- 组件代码应清晰易懂，结构合理
- 使用TypeScript进行类型定义，提高代码的可靠性
- 提供充分的文档和注释

### 3.4 性能优化原则

- 合理使用React.memo、useMemo、useCallback等优化手段
- 避免不必要的渲染和计算
- 考虑组件的懒加载和代码分割

## 4. 组件结构与组织

### 4.1 组件目录结构

```
components/
├── ui/                    # 基础UI组件
│   ├── accordion/        # 手风琴组件
│   ├── alert-dialog/     # 警告对话框组件
│   ├── button/           # 按钮组件
│   ├── card/             # 卡片组件
│   ├── input/            # 输入框组件
│   └── ...               # 其他UI组件
├── feature/              # 功能组件
│   ├── ai-chat/          # AI聊天组件
│   ├── growth-record/    # 成长记录组件
│   ├── homework/         # 作业组件
│   └── ...               # 其他功能组件
├── common/               # 通用组件
│   ├── header/           # 头部组件
│   ├── footer/           # 底部组件
│   └── ...               # 其他通用组件
├── internationalization/ # 国际化组件
├── performance/          # 性能监控组件
└── pwa/                  # PWA相关组件
```

### 4.2 组件文件结构

每个组件应包含以下文件（根据需要）：

```
component-name/
├── ComponentName.tsx     # 组件主文件
├── ComponentName.styles.tsx # 组件样式文件（可选）
├── ComponentName.types.ts # 组件类型定义文件（可选）
├── ComponentName.test.tsx # 组件测试文件（可选）
└── index.ts              # 组件导出文件
```

### 4.3 组件命名规范

- 组件名称使用帕斯卡命名法（PascalCase），如 `Button`、`ChatWindow`
- 组件文件名与组件名称一致，如 `Button.tsx`
- 组件目录使用短横线命名法（kebab-case），如 `ai-chat`、`growth-record`
- 避免使用缩写，除非是广泛认可的缩写（如 `UI`、`API`）

### 4.4 组件导出规范

- 使用命名导出和默认导出相结合的方式
- 默认导出主要组件，命名导出辅助组件和类型
- 使用 `index.ts` 文件统一导出组件，便于外部引用

```typescript
// components/ui/button/index.ts
export { default } from './Button';
export type { ButtonProps } from './Button.types';
```

## 5. 组件代码规范

### 5.1 TypeScript规范

- 使用严格的TypeScript配置
- 为所有组件定义Props类型
- 使用接口（interface）定义Props和State类型
- 避免使用 `any` 类型，除非确实无法确定类型

```typescript
// components/ui/button/Button.types.ts
export interface ButtonProps {
  children: React.ReactNode;
  variant?: 'primary' | 'secondary' | 'outline';
  size?: 'sm' | 'md' | 'lg';
  disabled?: boolean;
  onClick?: () => void;
  className?: string;
}
```

### 5.2 Props设计规范

- Props名称使用驼峰命名法（camelCase）
- 为Props提供合理的默认值
- 将复杂的Props拆分为多个简单的Props
- 使用 `optional` 标记可选Props

```typescript
// components/ui/button/Button.tsx
import { ButtonProps } from './Button.types';

export default function Button({
  children,
  variant = 'primary',
  size = 'md',
  disabled = false,
  onClick,
  className = '',
}: ButtonProps) {
  // 组件实现
}
```

### 5.3 状态管理规范

- 优先使用函数组件和Hooks
- 合理使用 `useState`、`useEffect`、`useContext` 等Hooks
- 避免在组件中管理过多的状态，考虑使用状态管理库（如Zustand、Redux）
- 使用 `useCallback` 优化回调函数，使用 `useMemo` 优化计算结果

### 5.4 样式规范

- 使用Tailwind CSS进行样式开发
- 避免内联样式，除非是动态样式
- 为组件添加统一的前缀，避免样式冲突
- 使用CSS-in-JS（如styled-components）处理复杂样式

### 5.5 组件文档规范

- 使用JSDoc为组件添加注释
- 说明组件的用途、Props、返回值等
- 提供使用示例
- 使用Storybook生成组件文档（可选）


## 7. 组件最佳实践

### 7.1 UI组件最佳实践

- 保持UI组件的简洁性和通用性
- 提供多种变体和尺寸
- 支持自定义样式
- 考虑可访问性（a11y）

### 7.2 功能组件最佳实践

- 封装复杂的业务逻辑
- 提供清晰的API
- 考虑错误处理和加载状态
- 支持数据的异步加载

### 7.3 业务组件最佳实践

- 与特定业务逻辑相关
- 组合多个UI组件和功能组件
- 考虑国际化和本地化
- 提供业务相关的功能和交互

### 7.4 Hooks最佳实践

- 自定义Hooks名称以 `use` 开头
- 保持Hooks的简洁性和专注性
- 提供清晰的文档和使用示例
- 考虑Hooks的性能优化

## 8. 组件测试指南

### 8.1 测试工具

- 使用Jest作为测试框架
- 使用React Testing Library进行组件测试
- 使用Cypress进行端到端测试

### 8.2 测试内容

1. **渲染测试**：测试组件是否能正常渲染
2. **Props测试**：测试组件对不同Props的响应
3. **交互测试**：测试组件的交互行为
4. **状态测试**：测试组件的状态变化
5. **边缘测试**：测试组件的边界情况

### 8.3 测试示例

```typescript
// components/ui/button/Button.test.tsx
import { render, screen, fireEvent } from '@testing-library/react';
import Button from './Button';

describe('Button Component', () => {
  test('should render button with text', () => {
    render(<Button>Click Me</Button>);
    expect(screen.getByText('Click Me')).toBeInTheDocument();
  });

  test('should call onClick when button is clicked', () => {
    const handleClick = jest.fn();
    render(<Button onClick={handleClick}>Click Me</Button>);
    fireEvent.click(screen.getByText('Click Me'));
    expect(handleClick).toHaveBeenCalledTimes(1);
  });

  test('should be disabled when disabled prop is true', () => {
    render(<Button disabled>Click Me</Button>);
    expect(screen.getByText('Click Me')).toBeDisabled();
  });
});
```

## 9. 组件性能优化

### 9.1 渲染优化

- 使用React.memo避免不必要的重新渲染
- 使用useMemo缓存计算结果
- 使用useCallback缓存回调函数
- 合理使用key属性，避免列表渲染时的性能问题

### 9.2 代码分割

- 使用React.lazy和Suspense进行组件的懒加载
- 按路由或功能模块进行代码分割
- 考虑组件的按需加载

### 9.3 资源优化

- 优化组件中使用的图片和媒体资源
- 使用Next.js的Image组件进行图片优化
- 考虑资源的预加载和预缓存

## 10. 组件可访问性

### 10.1 可访问性原则

- 确保组件对所有用户可访问，包括使用辅助技术的用户
- 遵循WCAG（Web Content Accessibility Guidelines）标准
- 提供适当的ARIA属性

### 10.2 可访问性实践

- 使用语义化的HTML元素
- 确保表单元素有适当的标签
- 提供键盘导航支持
- 确保足够的颜色对比度
- 提供适当的焦点状态
